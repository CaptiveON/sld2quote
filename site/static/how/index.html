How it works

Five stages, in plain language first

The pipeline follows the estimator's own take-off: read every word on the sheet, find every device, pair each device with its rating, check the drawing against the specification, then choose and price the parts. Each card below says what the stage does, why it matters to an estimator, and the number it was measured at. Every figure on this page is read from the evaluation files when the page loads.

Read the words

A text reader turns every label, rating and note on the sheet into text with a box.

An estimator's first pass is reading every rating; a misread "1600 A" becomes the wrong breaker.

 

Find the symbols

A detector trained on synthetic drawings finds each device symbol, reading the page in overlapping tiles and removing duplicates.

Every symbol is a line on the quotation; a missed symbol is a missing part.

 

Pair labels with symbols

Symbols on one vertical line form a way; the text lines stacked beside or below it form the way's label block; each block goes to the nearest way, preferring its own side, and each line is routed to a device by what it says.

A right label on the wrong symbol prices the wrong breaker. These rules were written against this generator's drawing conventions and tuned on the sets they are scored on, so the link numbers are an upper bound. The real project replaces the rules with a learned link trained on estimators' corrections.

 

Check the specification

The clauses are split and each requirement (form, fault level, IP, poles) is compared with the drawing; a disagreement becomes a question, never a silent fix.

A quotation that misses a clause is under-priced or non-compliant.

 

Choose parts and price

Fixed rules pick a catalogue part within the fault level, add busbars, enclosure, labour and documents, and name the evidence for every line.

The estimator checks each line against the drawing instead of trusting a total.

 

How to read the numbers: "symbols found" is the share of the answer key's symbols the reader found with the right type; "price within" is the gap between the quoted total and the total the same rules give on the answer key, so it measures reading, not pricing. The test set is synthetic drawings in the styles the detector trained on, none of which it saw in training; the unseen-style set holds whole drawing styles out of training. The Evidence page has every set, copy and device type.

The technical layer

What each stage does, in enough depth to check it

The same five stages, now with the mechanisms, the thresholds and the measurements behind them. Where a claim rests on published work, the bracketed number points to the References page.

Stage 1

Reading the words

The page is read at twice its size by RapidOCR, which runs the PP-OCR detection and recognition models through ONNX Runtime on two CPU threads [33][35][36]. Its bundled recogniser was trained for Chinese and drops the spaces in English labels, so the English recogniser from the same project's model repository is used instead [34]. A second, close-up pass around every symbol was measured and switched off for this engine: on our sheets it reads labels worse than the page pass and costs seconds a drawing ( of label characters right from the page against on scan-like copies). Known slips inside numbers on scans (a zero read as the letter O, a one as a lower-case L, a stray dot before a unit) are repaired where a number is expected; a meter whose tiny unit the page pass left empty is read again on its own at three times the size.

Measured on drawings, the text reader takes a drawing on the server's CPU, the largest share of the run.

Stage 2

Finding the symbols: tiles, one box per device, a threshold chosen on whole drawings, a calibrated confidence

The detector is RT-DETR with the r18vd backbone [20], fine-tuned from the published weights [22] through the Hugging Face transformers library [23] on tiles cut from synthetic drawings: training tiles holding answer-key boxes over symbol classes, from ( boxes) down to ().

Tiles and merging

A drawing is 1,600 to 4,300 pixels wide and a symbol 20 to 80 pixels, so the page is cut into 640-pixel tiles with a quarter overlap (stride 480) and each tile is read on its own. A detector of this family has no built-in rule against drawing two boxes on one symbol, so class-agnostic non-maximum suppression at IoU 0.5 is part of its output, within a tile and again when the tiles are merged. Two more merge rules were measured and kept: a box cut by an inner tile edge is dropped (the symbol is whole in a neighbouring tile), and a box that mostly contains a better-scoring one is suppressed. A quoting system must never count a part twice.

The operating threshold

The score threshold is not chosen on tiles. A threshold that maximises accuracy on validation tiles let the model draw boxes on blank paper once whole drawings were read, because a drawing is mostly blank and a tile is not. So the threshold is swept over the detector and the tile merge on whole validation drawings (seen and unseen styles pooled) and stored with the weights: the live model runs at , with boxes on blank paper across those drawings against at . Test drawings are never used for choosing anything.

Calibrated confidence

The number beside every device is not the detector's raw score. A DETR's scores rank boxes; they are not probabilities, and a page that painted every 0.3 box red was wrong, since on the validation drawings such a box was almost always right. Following the standard treatment of calibration [29], each model's weights carry a table from the same drawing-level sweep: for each band of score, how often a box in that band matched the answer key ( bands over boxes; the lowest band, to , reads ; from upward it reads ). The raw score is kept in the result for the record. On real drawings the calibration overstates, because they are not the drawings it was measured on; the page says so.

Per tile and per drawing

Per 640-pixel tile on the unseen-style test tiles ( tiles), the live model scores mAP@0.5 by pycocotools [28], with mean precision and recall ; classes meet the project's own bar of 0.95 precision and recall for every class. Those are a floor: a symbol cut by a tile edge counts as missed in that tile although the reader finds it whole in the next one. On whole drawings after merging, the measure the product is judged by, the reader finds of the test set's symbols with of its boxes right, and on the unseen styles. The detector takes a drawing on the server's CPU.

Stage 3

Pairing labels with symbols: the link rules and the role rules

The link is rules, not a second model. Symbols on one vertical line form a way (a chain, top to bottom). Text lines stacked at line spacing beside the chain's top device or below its bottom device form the way's label block. A block goes to the way nearest its first line, measured edge to edge between the symbol box and the text box, and a block that lies right of or below a symbol always beats one it lies left of or above, because the generator leaves the same gap on both sides and distance alone cannot decide. Each line is then routed to the device it names: a rating in amperes to the switching device, kW to the starter, kVAr to the capacitor bank, kVA and kV to the source, a CT ratio to the current transformer, a cable size to the way itself; text inside a symbol is its tag; what remains is the destination. A block that would give a device a second rating is left unlinked, so one missed symbol cannot misprice two ways.

The role rules then decide what each symbol is for: the main bus is the level carrying the most busbar length, a breaker is a bus-section when the bus passes through its box, and missing poles or fault ratings come from the notes block and are marked as assumed.

The link is scored on its own, apart from symbol finding and text reading: the generator records which device every text was drawn for, so link precision and recall count only links between a device the answer key matched and a text the reader located. On the test set the reviewed rules reach of the answer key's links and of ratings read right; on the unseen styles ratings fall to , mostly where a cable is drawn through its own label and the text reader returns a broken number. The caveat, stated plainly: the rules were written by reading the error lists of the same sets they are scored on, so those scores are in sample; the out-of-sample check feeds the answer key's own symbols and texts to the rules on fresh drawings used for no choice, where they make no link or rating error.

Stage 4

Checking the specification

The specification is split into clauses by their numbering, and each requirement the rules know (the standard, the form of separation, the fault level, the number of poles, the ingress protection, the busbar material) is read by pattern with the clause as its evidence. Each requirement is compared with what the drawing's notes block says; a disagreement is listed with both values and the clause, priced to the drawing, and raised as a question. The generator plants disagreements on purpose, so this stage has a score: on the clean test drawings the reader reports . Nothing is resolved silently, which is the behaviour the real project keeps when a language model replaces the patterns.

Stage 5

Choosing parts and pricing, with the evidence on every line

Deterministic rules over an invented catalogue: a breaker is chosen within the board's fault level by its rating, poles and the nearest frame size; busbars are priced as copper by weight from the busbar rating and the board's length; the enclosure from the form of separation, the ingress protection and the number of sections; then labour per functional unit, documents, delivery and a margin, all labelled illustrative. Every line carries the identifiers of the symbol box, the text box or the clause it rests on and the rule that chose it, so the estimator checks the line against the drawing instead of trusting a total. Anything doubtful becomes a question: a rating that could not be read, a device found with low confidence, a value assumed from the notes, a device whose rating sits below the fault level. On the test set the quoted total lands within of the answer key's total on clean copies and on scan-like ones, with of the reference bill-of-materials lines found. The specification check and the pricing take and : the time goes to reading, not to rules.

Why I used what I used

Every technology choice, with the reason and the measurement

RT-DETR over YOLO for the symbol detector
Two reasons, licence first. The most popular detector family, Ultralytics YOLO, is published under the AGPL-3.0 [25], which would oblige a company building on it to publish its own code or buy a licence; RT-DETR through the transformers library is Apache-2.0 [20][23], which a manufacturer can ship. Second, accuracy at real-time cost: the RT-DETR paper reports its r18 model matching or beating the YOLO models of its size on COCO at real-time speed [20]. The r18 backbone was chosen over r50 by a benchmark on this machine's CPU, where r18 reads a sheet in half the time, and by the overnight runs, where r50 scored lower on the unseen style and was twice as slow per pass.
Weight averaging, from the authors' recipe
Across the kept passes of one run, a device type's recall swung by up to a third between adjacent passes, so which pass was picked mattered more than any change under test. The authors' own training code keeps an exponential moving average of the weights and evaluates the averaged model, a part of the recipe the library port does not carry [21]. Added as one separately measured change, it gave the first model to beat the previous site model per tile and, at drawing level, the live model: pass of , chosen on whole validation drawings among recorded runs.
Selection and thresholds at drawing level
Per-tile scores and drawing-level scores disagreed twice: a pass that looked best per tile had stopped finding the box-style bus-section, and a threshold chosen per tile invented capacitors on blank paper. The product is a quotation for a whole drawing, so the best pass and the operating threshold are both chosen on whole validation drawings, with the test drawings untouched, and "boxes on blank paper" is reported as its own number.
Rare classes: repeat-factor sampling, tried and measured
The rarest symbols (relay, capacitor, surge arrester) were the weakest, so the LVIS method of showing tiles with rare classes more often [27] was tried. It halved the false alarms but the chosen pass lost the bus-section, which made every quote with one worse; the loss turned out to belong to the pass, not the sampling, which is why the pass-to-pass variance had to be fixed first.
RapidOCR over Apple Vision, because the server runs Linux and because it measured better
The first text reader was Apple's Vision framework [46], which only runs on a Mac. Five engines that run on Linux were measured on our own sheets against the generator's text: RapidOCR [33] reads the labels and notes at character accuracy in per standard sheet, against for Vision on the same pages, and it reads the held-out font and the single letters inside symbols that Vision skips. Choosing an engine by measurement on your own drawings, not by reputation, is the rule the real project keeps.
Synthetic drawings with answer keys
No public labelled set of single-line diagrams exists, and the company's drawings cannot be used before the project starts; the published work on engineering-diagram digitisation records the same scarcity [15]. A generator that draws the switchboards and writes every box, text and link gives a score for every stage, and recent work shows synthetic diagrams seeded from real topology can train a usable model before any real drawing is labelled [18]. The cost is honesty: the numbers are an upper bound, which is said on every page, and the generator is tested like code (no label over a symbol, every box on its ink).
IEC 60617 symbols from an open library
Symbols follow IEC 60617 [9], drawn in two breaker styles as UK drawings are. Seven symbol bodies come unchanged from the QElectroTech elements library [11] through a single-line-diagram set that converted them to SVG [12], under CC BY 3.0 [13] and credited; the rest are drawn in the generator to the same conventions. Realistic symbols are what make the numbers credible; a high score on three invented shapes would prove nothing.
Rules for linking, roles, the specification and the price, not a language model
Three of the five stages are rules, and that is deliberate. A rating, a form of separation or a fault level must never be guessed, and a rule can be read, tested and owned by the company's engineers. A published measurement of a fine-tuned vision-language model on engineering drawings reports an 11.5 per cent hallucination rate even on a narrow task [19], which is why the road map uses a language model only where it must cite the clause or abstain.
A free server that sleeps, with no secret
The demo runs on Google Cloud Run inside the free tier: the processor is billed only during start-up and requests [38], a start-up probe lets the page answer while the models load [39], live runs are capped per day, and the model is copied into the image so the service holds no token at all. The API is FastAPI [48]; a static copy of the samples on a Hugging Face Space [47] is the fallback when the server is asleep or gone.
Plain HTML, CSS and JavaScript for this site
No framework and no build step, so the pages can be read, served from any static host and checked by anyone. Every number is parsed from the evaluation files at load time, the charts are plain SVG drawn from the same files, and the design keeps to WCAG 2.2 targets for contrast, focus and target size [49].

The decisions behind these choices, each as problem, options, decision and result, are on the Decisions page; the measurements are on the Evidence page.
